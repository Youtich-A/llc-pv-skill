# 全片分析、分段制作与上下文控制

## 项目文件约定

```text
project/
  project.md                全局约束与简短段落索引
  state.json                当前段/镜头/阶段/门禁与文件路径
  shared/                   母音轨、角色规范、色板、共享素材注册表
  segments/
    P01/
      segment.md            本段目标、范围、镜头索引和边界
      assets.md             仅本段资产需求及共享资产引用
      shots/S001.md          每镜唯一任务说明
      shots/S002.md
      evidence/             本段原片/制作图版和manifest
      review.md             三轮与质量核对
      feedback.md           本段反馈、问题ID、修订结果
      accepted_handoff.md   肯定后精简交接
      renders/              本段版本预览
    P02/                    内容独立，不复制进P01
```

工程可共享以利合并，任务文档必须隔离。共享资产允许单一物理副本，通过资产ID/路径引用；不能因目录分段而复制出多份互相冲突的母音轨。

## 分段算法（人工判断镜头语义）

1. 通读全片，记录镜头边界和曲目章节。约2分钟通常需要约6段工作单元，实际段数由镜头密度与动作边界决定。
2. 原有约30秒目标统一调整为约20秒，尽量不超过25秒。优先在25秒以内选择接近20秒的自然边界，例如0–19.2、19.2–40.0秒；高密度内容可以更短，不为凑20秒合并过多事件。
3. 接近25秒仍无可用切点时，在连续长镜的动作阶段设置内部工作段/检查点，保留父级、相机、物理和音乐相位，不把工作分段误当视频硬切。确需超过25秒须记录原因、交接和检查点；不能因素材恰好30秒而整段一次制作。已有明确通过或用户指定范围的历史段不自动切碎，未开工后段按新规则规划。
4. 区间采用半开 `[start_frame,end_frame_exclusive)`；每帧归属唯一，预览证据可在边界两侧多读少量把手帧，但不重复计入最终片。
5. 每段保留全局音乐时间和本地时间：local = global - segment_start。保留帧/PTS映射、相位、首尾交接状态。VFR不能直接用帧号除以标称帧率。

## 规划与制作的加载规则

全片观察时允许访问全部视频；只写紧凑结构索引。路线确认后详细脚本可以按段依次写完，不得一口气加载整片高密度正文。第一段不放第二段脚本。

在制作S001前，将全局必要项、通过段已确认的共用规则、本镜头用户最新要求、资产路径、边界状态摘入S001。加载后该文件就是当前镜头唯一任务说明；工具文档、素材和证据可按需读取。发现缺项先补本文件，不靠临时聊天记忆。

读取文件不会自动清除模型已有上下文。通过短摘要、停止重复读旧稿和任务切换检查点控制注意力；接近上下文上限时先保存state与当前镜头进展，再用宿主支持的压缩/恢复方式继续，不声称技能能够自行清空上下文。

## 状态与门禁

`environment_check → intake → overview → asset_route_pending → scripting → asset_check → asset_ready → production → review_1 → review_2 → review_3 → quality → user_review → accepted → handoff → next_segment`。

用户已选路线可跳过asset_route_pending；技术检查失败回到production/对应轮次，用户否定回到feedback/修订。未收到明确肯定保持user_review，不得写accepted。通过需记录用户原话、对应视频版本和适用范围。

段P01未通过时，可维护全局索引和已经授权的必要共享资产；不得以“提前准备”为由批量生产P02资产或开始P02工程。后段用户提出的新全局约束需要回归前段受影响内容。

文件写入可记录门禁，但没有宿主控制器时无法物理阻止违规执行。执行者必须遵守该规则，并如实报告检查状态。
