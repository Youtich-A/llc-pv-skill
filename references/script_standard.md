# 高信息密度镜头脚本标准

按“镜头 → 系统 → 元素/部件 → 事件”拆分。元素表写有什么与归谁管，事件表写何时从什么变什么，关系表写父子/接力/遮挡，检查表写如何证明完成。使用[独立镜头模板](../templates/shot.md)。

## 需求过量时继续拆，不压缩掉细节

先写全片紧凑索引和章节表，再逐镜书写。单镜事件过多时用`shots/S007/index.md`保存必要约束、总范围和子文件索引，按事件/阶段分为`entry.md`、`hold.md`、`exit.md`等；也可按独立系统拆。子文件只继承当前任务所需约束，跨文件接口写清时间、父级和稳定实例ID。不要把同一个字跨阶段误建成不同实例。

制作时先读当前镜头主文件，再仅加载当前事件/系统所需子文件与引用素材/证据；切镜后保存状态，不批量读回其他镜头正文，不把所有子稿再次合成巨稿。细节不足先补当前文件，不用“整体动画”“背景复杂”“照原片”替代事件。分拆是注意力管理，不声称工具能清空模型记忆。

## 一镜必须自足的信息

- 身份：段ID、镜头ID、脚本版本、工程/合成、当前阶段。
- 继承约束摘要：本镜头适用的用户原话、最新纠正、保持项/允许差异、废弃方案。
- 时间：全局帧/PTS、本地时间、帧率、半开区间、音乐触发点与未听校项。
- 章节：intro/verse/chorus/interlude等标签、所属章节ID、置信度/听校状态；前奏、间奏、副歌的增强质量目标。
- 完成态：文字逐字原文、主次读序、字体/字重、字距、颜色、可见墨迹宽高、画面占比、角色脸/手/脚定位、负空间。
- 资产：唯一ID、用途、文件/源合成、透明度、分辨率、裁切、朝向、更新/复用路线及状态。
- 关系：元素和实例ID、锚点、坐标系、父级、深度、谁遮谁、效果归属、共享时间与复用身份。
- 空间与完整背景：2.5D/3D路线及依据、近中远构造、四角与画外延展、密度/分布、遮挡发生和解除；明确哪些变化由相机承担。
- 阶段：出生前、首次可见、预备、峰值、落定、持有期内部变化、二次启动、退出、消失后。不存在的阶段标不适用。
- 动作：各阶段的起止与中间姿态、位移/缩放/旋转/斜切、速度/加速度、停顿、过冲、回弹、相位、碰撞因果。
- 外观：填充/描边、闪色/负片、Alpha、模糊、残影、粒子、纹理与抽帧通道及持续帧数。
- 共同系统：父级和相机同时做什么，后期栈顺序；区分局部动作、组级运动与最终画面效果。
- 交接：前镜末态的必要摘要、本镜末态、下一镜接口；仅写相关接口，不粘下一镜全文。
- 验收：事件ID→工程图层/属性→渲染帧/证据；已做、未做、差异与未知。

不为凑密度堆无关字段。没有证据的精确值写“待测”或“重建选择”，不得伪称作者参数。文字内容不是图层唯一查找键，重复字必须分实例ID。

对不明风格化单列“可见证据/候选机制/待问问题/用户答复/截图授权范围/阻塞项”，用户说明后再定实现路线。已有明确答复直接继承，不重复索取。

## 足够密度的实例

**アイス接力思路：** “青向左上移动”不够。应写：同一实例先属于第一字组；在持有结束前保持；转移从明确帧启动；主要位移发生在哪几帧；第二幕的描边切换另列事件；父级持续后退不停止；第二段目标键不能提前拉动第一段。

**衛星朝向思路：** “花束旋转”不够。应写：花头在上枝柄在下；屏幕投影轴保持竖直；内部绕轴方向、范围与时间；屏幕Z旋转、相机、父级各自约束；独立照片卡固定角度；材质色阶和轮廓分别验收。

**角色手势实例：** “点赞入场”不够。应写：四指拳头先出现；独立拇指藏在拳后；与人物退后/踢腿相同事件触发展开；支点在指根；短促过冲再回摆；拳头组轻倾；近景版本重新校准遮挡和幅度。

这些例子只示范信息密度，不能直接照搬旧片时点、坐标、BPM或材质。
