# 自检执行强度与重复观看预算

三轮完整对照的质量标准对所有模型相同。这里调整的是执行辅助和记录强度，不能以模型品牌减少轮数、跳镜头或免除已知问题修复。

## 选择模式

用户可指定 `strict`（加强执行约束）或 `compact`（精简辅助）。未指定时，按本项目约定：DeepSeek、Kimi、GLM 等先用 strict；GPT、Gemini、Claude 等先用 compact；模型未知或工具调用/文件记录能力不稳定用 strict。这只是用户指定的工作流初始策略，不是模型能力排名。若宿主不暴露模型身份，不猜型号。

出现跳轮、只看几个镜头、伪造观看状态或修复后未回归，切换 strict 并记录原因；执行稳定后可精简辅助。模式只记录在项目状态，不改全局宿主配置。

## compact：把检查集中到正式三轮

- 制作期间只做决定路线的机制小样、真实错误诊断、必要技术检查；普通视觉微调进入本轮问题队列。
- 每轮保留一份简短逐镜覆盖表和完整问题集，不复述已完成步骤，不为了“放心”反复读整片或整份脚本。
- 第三轮已覆盖最新版本、未解决问题已清零、技术输出有效时直接交付。不得在输出前再自发增加第四次完整视频观看、无限“最后再看一遍”或要求模型内部证明自己满意。
- 动效/卡顿核对尽量并入三轮的实际有声播放与证据记录，避免把“独立质量项”误当第四轮全片观看。尚无有效播放证据时补齐一次必要检查。

## strict：用可观察记录约束跳步

以模板 [review_execution.json](../templates/review_execution.json)落盘：全部镜头 ID、原片全片范围、当前授权段范围、各轮命令、manifest、实际查看证据、完整问题 ID 和最新输出版本。每轮完成前更新一次，不在每个工具调用后再追加一份重复总结。

每轮必须满足：

1. 顺序进行 1→2→3；未完成当前轮不将后轮标通过。
2. 本轮重新调用 video-watch，并实际查看覆盖原片全片及当前段最新完整输出；所有镜头逐项记录，包括没有问题的镜头。
3. 先遍历完整范围，列出完整问题集合，再集中修复。已知本轮问题未关闭、盲区未补读或缺少证据时保持 pending。
4. 修复后记录同窗复核与最新整段回归；该轮通过绑定到真实版本。后轮结构修改会使关联旧证据失效，做受影响回归，不机械从零重跑全部三轮。
5. 交付前运行 `python scripts/validate_review.py <项目中的review_execution.json>`。它只检查声明、文件存在和覆盖数据的一致性，不能证明模型实际看过或画面正确；不得通过填空或改写状态骗过检查器。

验证失败时修记录中的实际缺项；无工具、无渲染或无观看能力时如实标未完成，不虚构 evidence 文件。简版模式也可使用同一脚本；用户明确减免检查时按主验收规则记豁免，不能把减免伪装成 validated。

## 何时可以追加检查

出现具体新证据才追加：解码/导出失败、文件版本变化、全局相机或字体改变、用户新反馈、参数接缝穿帮等。写明触发原因和受影响镜头，优先局部或关联范围回归；只有影响整段时才重新通看整段。没有新变化的旧风险猜测不能触发额外全片观看。

始终区分“生成图版”“打开看过”“只做量测”；本轮可重新调用工具复用未变素材的解码缓存，但必须产生本轮记录并重新查看，不把上一轮视觉结论复制为本轮观看。
