# 最开始的环境检查与本地AE MCP连接

## 检查顺序

本机缺少服务、组件或依赖时，先提供[下载渠道与受限环境接入](downloads.md)，包括AE MCP官方GitHub/npm和video-watch包内位置。用户不能直接联网安装时给出手动下载/转移路径，再恢复连接检查。

1. 确认本轮目标和执行软件已有答案。仅分析无需修改AE；AE制作必须先完成本节。
2. 运行包内 `python components/video-watch/vw.py doctor`，记录实际Python、FFmpeg/ffprobe、ImageMagick及字体结果。ASR/OCR按需启用，不因可选项缺失阻塞不需要它的任务。
3. 核实Node.js >=24、合法可用的AE安装及MCP客户端。AE 2024–2026 / Windows、macOS是上游声明范围，具体能力仍按当前版本返回。
4. **发现真实工具接口。** 查当前客户端是否暴露aftereffects服务的 `ae_context`、`ae_version_info`、`ae_catalog`、`ae_do` 和 `ae_render_frame`。前缀可能不同。只看到包已安装或Node进程存在不能证明模型能调用MCP。
5. 已配置就沿用，不覆盖宿主配置。缺配置时准备当前宿主支持的局部配置；在用户授权范围内接入。不要复制别人机器的可执行文件路径、项目路径或私有环境变量。
6. AE中打开目标工程或明确授权的工作副本，并开启“首选项 → 脚本与表达式 → 允许脚本写入文件和访问网络”。macOS按系统要求允许客户端自动控制。多实例须明确选择正确工程/实例。
7. 首先只读调用 `ae_context` 与 `ae_version_info`，核对工程、dirty状态、活动合成、AE版本、实例、能力与undo契约；再用 `ae_catalog` 查询需要的操作及策略。结果包含敏感路径，只存本地环境记录。
8. 任务需要制作时，确认不是只读策略，当前类别允许需要的操作。只在已授权的测试工程/工作副本创建最小测试合成，放一项可辨识内容和简单时间变化，用 `ae_render_frame` 渲染至少两个时间点并看图。保存到本次独立输出路径，不覆盖用户文件。缺少测试授权时先记录“只读连接成功，写入/渲染待验证”，不额外操作工程。
9. 记录[环境检查表](../templates/environment.md)；本段制作依赖的字体、素材、输出模板随后按脚本核对。

`file:null / numItems:0`只能说明空工程，不能自动调用project.new清空状态。`instances:[]`或工具返回成功本身也不足以证明已命中目标工程，必须核对真实工程/实例信息。

## 通用注册示例

上游：https://github.com/kumoproductions/mcp-aftereffects 。本包携带连接和操作说明，不捆绑服务端及其node_modules。参考版本0.3.1；2026-11-06核实npm发布0.3.2，修复了SDK及相关依赖安全问题，因此新接入示例固定为0.3.2。已有环境不自动升级；未来更新前查上游变更和实际schema。

通用MCP JSON（适用于支持该配置形态的客户端，不能直接当所有宿主的配置文件）：

```json
{
  "mcpServers": {
    "aftereffects": {
      "command": "npx",
      "args": ["-y", "@kumoproductions/mcp-aftereffects@0.3.2"],
      "env": { "AE_MCP_READONLY": "1" }
    }
  }
}
```

先检查可用的npx可执行入口；Windows某些宿主需要npx.cmd或已安装包的node入口。生产时可用本地固定版本和锁文件减少临时下载。`npx -y`首次执行会下载包，不是离线检查命令。

只读示例便于先检查。制作需要在当前授权范围内移除只读限制，重连后回读策略确认；不要默认开启任意脚本。`AE_MCP_ENABLE_EVAL`默认保持禁用。

非标准AE位置在**本地配置**加入 `AE_MCP_EXE`（Windows为AfterFX.exe，macOS为.app包路径）。示例不附真实路径。需要多实例时按上游install-agent/agent-status流程安装用户级启动脚本并正确选择 `AE_MCP_INSTANCE`；这属于安装变更，不在只读检查时偷偷执行。

## 故障定位

|现象|检查和处理|
|---|---|
|没有AE工具|客户端是否注册/启用服务、服务启动日志和会话是否刷新；没有工具则无法通过该MCP操作AE|
|Node启动失败|Node版本、命令入口、包版本、安装完整性；不把npx下载错误归为AE错误|
|NO_INSTANCE|AE是否运行、目标实例是否正确、仅-m实例是否缺agent、模态窗口是否阻塞；不启动错误空实例冒充成功|
|DIALOG_OPEN / 超时|读错误详情；处理缺素材、许可或保存提示需要具体选择时交用户，不强杀AE或自动丢弃修改|
|只读成功但不能写|AE脚本权限、READONLY、操作类别策略和当前schema；读取成功不代表写权限|
|参数被拒绝|重新查ae_catalog；不要猜参数、忽略校验或启用eval绕过|
|渲染异常|合成/时间/输出路径、帧范围、工作空间与colorWarning；实际读PNG检查|

一次失败先定位，最多做一次有依据的修复重试；相同错误持续时保存状态并说明具体阻塞，不循环启动进程或重复写入。

## 隐私边界

AE返回的工程名、图层名、表达式、素材路径和截图可能进入所选模型服务和客户端日志。运行数据留在项目工作目录，不能自动提交到技能仓库。开源只发布通用配置样例，真实配置、环境报告、AEP、预览、原片和邮箱runtime目录不随包发布。
